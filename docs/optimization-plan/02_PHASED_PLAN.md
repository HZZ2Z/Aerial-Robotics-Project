# 分阶段实施计划

按 P0→P6 顺序推进。阶段完成由证据决定，不以“脚本已编写”“目录已创建”代替通过。允许并行阅读、文档准备和不同文件的独立实现；核心结果必须在同一已冻结版本上串行验收。

## P0 冻结基线与环境入口

目标：保留历史证据，明确可运行环境，避免基线错误被后续结果覆盖。

1. 读取目标仓库及父目录AGENTS.md、检查`git status`，记录HEAD和用户未提交内容；不要强制reset。若HEAD不同，先对照本包关键文件重新定位已修/未修问题。
2. 新建本地工作分支，例如`fix/course-validation`，不默认推送远端。
3. 将旧README指标标注为历史风场版本；在新运行目录写入版本与配置标识，防止覆盖旧结果。保留旧日志只供追踪，不将其作为正确性能基线。
4. 核查MATLAB、Simulink、Control System Toolbox与视频输出依赖，记录确切版本。先检查许可证和函数可用性，再运行昂贵仿真。
5. 选定唯一公开入口：根目录新增薄入口`main.m`，原`matlab/main.m`改名为`run_project.m`函数。根入口只解析根路径、添加路径、调用函数；不要出现同名递归或在公开入口中`clear`清掉调用者数据。
6. 在首次调参前冻结开发种子1729和holdout种子1009/2027/4093/8191/16381，P4只执行这些预定验证，不依据结果挑种子。
7. 执行现有线性设计/plant检查并保存真实输出。无MATLAB时可以进行静态核查，但相应动态检查标为BLOCKED。

交付：基线记录、依赖清单、历史结果标识、可定位错误的根入口。通过条件：版本可追踪，运行目录不混用，环境缺失有明确诊断。

## P1 修复实验输入与真实信号

目标：输入、实际plant和日志三者一致。

- P1.1 修改`build_closed.m`风场接线：均值与阵风汇合、应用场景开关后，形成唯一`vw_applied`，同一信号接plant和日志。
- P1.2 修正OU滤波器至极点−1/τ；统一噪声强度、相关时间、种子配置。移除未解释的固定gust_power=4校准常量。
- P1.3 提供`none / mean_only / mean_gust`风场配置；用于组件验证的`gust_only`可以保留，不增加任务平台。
- P1.4 将课程传感器模型明确为连续真值＋谱密度r的有限带宽白噪声近似，噪声更新在固定网格进行；不可在ODE每次Derivatives调用中直接随机抽样。若保留旧整体sample-and-hold，只作为标记清楚的独立扩展。
- P1.5 记录真实施加的风、时延后且饱和后的执行器输入、真实姿态/速度、滤波器实际使用的模型加速度；统一物理扰动和有效预测残差的定义。
- P1.6 修正完整GNSS断测状态序列：good→no_fix→good；普通RTK失锁为good→degraded→good。明确区间采用[t0,t1)。

详细实现：[03_PHYSICS_ESTIMATION.md](03_PHYSICS_ESTIMATION.md)。

通过条件：无风输入恒为零；关闭阵风的均值阶跃在15秒准确施加；plant/log风一致；OU时间常数与稳态方差有组件证据；GNSS两类失效与恢复状态正确。完成这些才开展新的KF调参。

## P2 恢复课程估计器基线与有效统计

1. 在现有函数体系中集中生成KF矩阵：正式模式`rw9`，扩展模式`ou_bias12`。两种模式均输出[p,v,d_total]以及对应9×9输出协方差，内部状态维度明确记录。
2. 为两套模式计算good/degraded稳态增益，保留可观性和Hurwitz检查。课程基线默认硬切换；1.5秒增益软恢复属于扩展配置，须单独记录。
3. 独立传播误差协方差，使用与实际L(t)、R(t)、模型模式相同的配置。无需把固定增益滤波器改成时变Kalman滤波器；推荐先离线基于相同记录传播P，避免增加在线代数环。
4. 删除把偏置状态当计时器的逻辑，使用模型维度导出的索引或具名字段。修正P输出/日志链路。
5. 修正零中心±3σ图，输出逐轴覆盖率、NEES、创新均值与时间序列。用模型匹配的线性试验校验统计计算，再解释非线性任务的模型失配。
6. 重写旧qa/qd扫描，参数与当前模型模式一致。先固定合理参数完成基线验证，随后再用小规模对照判断12状态扩展是否必要。

通过条件：两种模型接口一致，9状态任务可运行；无虚假置信图；失锁时P可随时间变化；创新和误差真值可追溯。NEES偏离维数应如实分析，不得靠扩大Q/R只为把统计量“调到合格”。

## P3 补齐控制实验与可选加分

- 同一任务/风/传感器/种子下比较ρ=0.1/1/10；控制努力使用固定归一化R0，不把被扫描ρ乘进比较指标。
- 按标准10%→90%定义上升时间，2%带定义稳定时间；若只使用初值误差衰减，则明确命名，不伪称参考阶跃响应。
- 用专门的静止悬停试验验证积分消除恒风偏差，窗口与任务段一致，不包含八字或降落。
- 统一`q_maneuver`专用机动参数构造，主入口和独立脚本共用；输出文件名包含实验ID。
- Bonus前馈改为`a_ref-d_hat`，先用无噪声解析工况检查符号，再比较纯积分与积分+前馈。GNSS完全中断分别量化1秒和5秒漂移。
- 35°使用实际姿态计算并检查，不硬裁剪R/Euler状态来“修正”结果。

详细实现：[04_CONTROL_EXPERIMENTS.md](04_CONTROL_EXPERIMENTS.md)。

通过条件：必做三权重、精确Q和恒风积分试验具有数据/图/解释；Bonus不通过不阻断必做成果，但不能声明加分项已完成。

## P4 全场景结果与回归

1. 正式rw9基线运行10个核心场景：ideal/estimated × nominal、wind、rtk_lost、uncert_Jplus、uncert_Jminus。后两个共同构成课程第(iv)类场景，均mass+20%且delay20ms。
2. 冻结指标定义：3D位置RMS、最大3D误差、悬停偏差向量及范数、各状态RMS、最大倾角、控制努力和执行器饱和比例。表格不得混用每轴平均RMS与3D向量RMS。
3. 使用同一源噪声完成代表性dt=1ms与0.5ms对照。固定噪声相关时间，避免把“换噪声”误判为求解器差异。预先建议2%相对指标差异作为调查线，接近零使用明确绝对容差；不是课程官方门槛。
4. 使用P0已冻结的开发seed与5个未参与调参的验证seed。只对estimated的wind和rtk_lost两个关键场景做少量保留验证，不把20次旧参数搜索当20次MC。
5. 如展示ou_bias12优越性，在相同场景/种子/指标下追加对照；不能仅挑有利场景或删掉失败种子。
6. 输出结构化metrics与manifest，标记核心/扩展/Bonus及配置。任何FAIL需保留原因。

通过条件：核心10场景有完整结果，未出现未解释的非有限状态或硬约束越界；所有图表使用同一结果版本。详细阈值和证据见 [05_ACCEPTANCE_AND_REPORT.md](05_ACCEPTANCE_AND_REPORT.md)。

4. 完成6页IEEE双栏PDF，人工核查图、单位、参数和页面可读性；姓名学号由真实资料填入，缺失时单独标记。
5. 修正README入口、路径、工具箱和归档autoresearch脚本路径。若归档只供历史阅读，则明确“历史记录”，不宣称开箱可运行。
6. 从指定版本清洁导出提交ZIP，包含所需MATLAB代码/模型和README；论文PDF单列并可在交付总包中一起提供。不要打包缓存、个人临时目录或未授权材料。

通过条件：论文无数值/文本占位和未解析引用；6页；包中入口可用，图表和报告数字一致。缺身份资料不阻断其他技术工作，但不能把论文标记为完全可提交。

## P6 冻结版本与复跑

冻结源代码提交、参数、种子、工具版本、模型/脚本哈希和数据摘要。从新的导出目录运行`full`，自动创建新的execution_id批次；保留随包冻结批次作为参照，不覆盖它。保存日志、退出码、结果清单和RERUN记录。对照冻结指标使用已记录容差；相同环境可要求精确或极小差异，不把跨版本浮点bit-exact作为无条件承诺。模型重新保存可能改变二进制元数据，检查接线和配置语义，不只比slx字节。

任何源代码或最终参数再变化，都需要标记旧复跑证据过期，并按影响范围重新验证；仅文字排版修改重编译和检查论文，无需重跑全部仿真。所有技术结果与交付文件完成后停止追加优化。

## 执行预算与停止规则

优先先完成一个正确的9状态端到端任务，再扩大到核心10场景；不要每改一行就跑全套。实际单次耗时在P0测量，完整预算按已测耗时乘运行数估计，不沿用README的固定30分钟承诺。

遇到环境或授权阻塞，完成仍可独立执行的代码/静态检查/文档，并提供准确命令和缺失依赖。没有动态证据的阶段不能置为PASS。实施计划已经授权的本地可逆修改无需反复请求确认；远端推送、发PR/评论和发布需要会话中已有对应授权。
